## Gap 목록

### Gap-1 (Low) — §7 테스트 케이스 표기 미세 불일치
- T7 검증 인덱스(`out[98]`=99번째=`-99`)는 동작상 정확하나 설계표 1-index와 표기 어긋남.
- T9 입력이 설계(과목 cv_etc="")와 달리 cv_id=999(미존재→null)로 검증. 결과(`자-`)는 동일.
- 9케이스 전부 실질 커버 + 방어 테스트(빈 입력) 추가. **조치 불필요 수준.**

### Gap-2 (Medium) — income(수입)이 공유 API로 함께 변경됨 + 수입엔 약자 데이터가 빈약
설계 §9 D-5("범위=지출만")·§10("비변경: income 경로")와 **실제 동작이 모순**. income(`income/page.tsx:146`, `incmSecCd=1`)이 동일 `batch_receipt`를 호출하므로 §6 변경이 income에도 적용됨(alert도 수정됨).

**수입 prefix 실측 (INCM_SEC_CD=1)** — 핵심 발견:

| org type | 수입 prefix 실측 | 효과 |
|---|---|---|
| **후원회(91/92)** | 전 과목 cv_etc 빈값 → prefix `""` | **전부 `01,02,03…`** (계정·과목 미반영, 기존 전역순번과 사실상 동일) |
| **정당(50~53)** | 대부분 과목 cv_etc 빈값(당비·기탁금·보조금·차입금…), 일부만 `상-`/`하-` | prefix `""`(`01..`)·계정약자만(`경상-01`)·`경상-상-01` **혼재** |
| **후보자/국회의원(54/90)** | 지출과 동일 코드(82~85/86·87) 공유 | `자(비)-01` 등 정상 |

→ **수입은 과목 약자가 대부분 비어** 사용자 기대("계정·과목 반영")가 충족되지 않음. 특히 후원회 수입은 prefix가 전혀 없어 `01,02…`만 부여. 동시에 income의 동작이 **"빈것만 채우기+전역순번" → "전체 재생성+prefix그룹순번"** 으로 바뀜(정당 수입은 빈prefix/계정약자 그룹이 분리돼 기존 통합순번과 다른 결과).

**판정**: 기능 오류(crash·잘못된 번호)는 아니나(fallback 정상), **설계 범위 선언과 실동작 불일치 + 수입 사용자가 예상치 못한 동작 변경**. → 사용자 결정 필요.
