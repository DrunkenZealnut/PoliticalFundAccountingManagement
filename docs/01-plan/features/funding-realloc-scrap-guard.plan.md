# Plan — 자금원 재배분 소액 자투리 방지 + 지출 자금원 보호 (funding-realloc-scrap-guard)

- 기능: `funding-realloc-scrap-guard`
- 단계: Plan
- 작성일: 2026-07-01
- 유형: 후보자 회계 재배분(Pass1 fund-realloc) 알고리즘 개선 (보고 시점, 원본 불변)
- 관련 메모: [[fund-source-redistribution]] · [[income-expense-book-funding-realloc]] · [[income-expense-item-allocation-persist]] · [[settlement-must-use-realloc-ssot]] · [[export-db-accbook-split-bak-raw]]

## Executive Summary

| 관점 | 내용 |
|------|------|
| **Problem** | 재배분(Pass1 `fund-realloc`)이 지출을 **시간순 그 시점(as-of) 가용**으로만 충당해, 원 자금원에 **소액 자투리**를 남긴다. 오준석 실데이터: 확성장치 540,000원(자금원 84 후보자자산)이 5/22 시점 84 가용이 58원(예금이자 57+네이버 1)뿐이라 `84:58 + 83:539,942`로 쪼개지며 **58원 자투리** 발생. 84는 총액이 413,483원 부족(총지출>총수입)이라 84 지출 일부의 이동 자체는 불가피하지만, **확성장치처럼 통째 유지해야 할 지출이 쪼개지고 무의미한 소액 조각이 생기는 것**이 문제. |
| **Solution** | Pass1 이동 로직을 개선 — **원 자금원 잔류가 소액 자투리가 되는 부분충당을 회피**하고, 부족분을 **통째 이동 가능한 다른 지출**로 충당해 확성장치 등은 원 자금원에 온전히 남긴다. 자금원별 수입합·지출합·통장 총잔액·지출 과목은 **불변**. |
| **Function/UX** | 수입·지출부(뷰어·HWPX·결산·자료백업 .db)에서 58원 같은 무의미한 자투리 조각 제거. 지출은 통째로 원 자금원 또는 단일 이동 자금원에 배치되어 장부 가독성·자금원 정합 향상. |
| **Core Value** | 회계장부에서 재배분 자투리 제거 + "자산으로 산 지출은 자산 자금원 유지" 정합 + 원본 acc_book 불변·합 보존. |

## 1. 배경 / 재현 결과

### 1.1 재현 (Supabase org11 = 지출내역 페이지 원본, 80행)
최신 `buildLedgerRows`(Pass0→1→2) 적용 결과:
- 원본 80행 → 재배분 후 91행, **자금원 이동 조각 8개**.
- **확성장치 #331 540,000원(자금원 84)** → `84/86:58` + `83/86:539,942`. **58원 자투리.**
- 원인: 5/22 그 시점 자금원 84 가용 = 58원(예금이자 57 + 네이버페이 1)뿐 → `fund-realloc.ts:115`가 그 58원을 먼저 써버려 84에 58원 잔류.

### 1.2 자금원별 총액 (핵심 제약)
| 자금원 | 총수입 | 순지출(환급 반영) | 판정 |
|--------|-------:|-------:|------|
| 83 보조금외 | 3,000,000 | 3,000,000 | 균형 |
| **84 후보자자산** | **22,502,579** | **22,916,062** | **413,483 부족** |
| **85 후원회기부금** | **9,430,000** | **9,016,517** | **413,483 잉여** |
| **통장 전체** | **34,932,579** | **34,932,579** | **0 (정상, 대시보드 일치)** |

- **84는 413,483원 부족, 85는 정확히 413,483원 잉여** → 84 부족분을 85 잉여로 충당하는 것이 재배분의 정당한 목적. **통장 총잔액 0**이라 진짜 부족 없음(데이터 정상).
- **환급 반영 필수**: #367 문자환급 **−108,583원(85, 과목86)**을 순지출에서 빼야 통장 0이 된다. (첫 재현이 `acc_amt>0` 필터로 환급을 누락해 통장 −108,583으로 **오판 → 정정**. [[negative-refund-rows-in-aggregation]].)

### 1.3 근본 원인
- `lib/accounting/fund-realloc.ts:115` `useS = Math.min(need, Math.max(0, get(S)))` — 원 자금원 S에 부족분보다 적은 소액만 있으면 그 소액(useS)을 먼저 써서 자투리를 남긴다.
- v0.24.0.0 자투리 방지(`126-137`, "단독 충당 우선")는 **다른 자금원으로 이동하는 조각의 자투리만** 막고, **원 자금원 잔류(useS)** 는 대상이 아니다.
- 시간순 as-of 판단이라, 84처럼 **미래에 큰 수입이 들어올** 자금원도 그 시점 부족하면 지출을 쪼갠다.

## 2. 목표 / 비목표

### 2.1 목표
- 재배분이 만드는 **소액 자투리 조각 제거**(임계값 이하 원 자금원 잔류 방지).
- **확성장치 등 통째 유지 가능한 지출**은 쪼개지 않음(이동은 다른 통째 이동 가능한 지출로).
- 불변식 유지: 자금원별 수입합·지출합, 통장 총잔액, **지출 과목(86/87) 불변**, 원본 acc_book 불변.
- 결정적(deterministic)·전 산출물(뷰어·HWPX·22-1·결산·.db) 일관.

### 2.2 비목표
- **통장 총잔액 부족(-108,583) 데이터 보완** — 수입 누락 점검은 별도 작업(§6).
- Pass2(과목 재태깅) 변경 — 본 건은 Pass1(자금원)만.
- 진짜 총액 부족 자금원의 부족분을 0으로 은폐 — 하지 않음(경고 유지).

## 3. 기능 요구사항 (FR)

- **FR-1 (원 자금원 잔류 자투리 방지)**: Pass1에서 지출을 재배분할 때, 원 자금원 잔류(useS)가 소액 자투리(임계값 미만, OQ-1)가 되는 부분충당을 피한다.
- **FR-2 (통째 유지/이동 우선)**: 자금원이 총액 부족해 이동이 불가피하면, **부분 분할로 자투리를 만드는 대신 통째 이동 가능한 지출을 골라** 부족분을 충당한다. 확성장치처럼 큰 지출은 원 자금원에 온전히 남기거나 통째 이동.
- **FR-3 (불변식 보존)**: 자금원별 수입합·지출합·통장 총잔액 불변, 지출 과목 불변, 원본 불변. Pass2·영수증 채번([[income-receipt-no-omitted]])과 충돌 0.
- **FR-4 (자금원 잔액 정책 결정)**: 현재 불변식은 "시간순 자금원 잔액 ≥0". 통째 유지/이동을 위해 **중간 시점 음수를 허용할지(총액 기준)** 를 Design에서 확정(OQ-2). 공식 프로그램(Fund_Data) 형식 정합 확인 필수.
- **FR-5 (전 산출물 parity 회귀)**: `buildLedgerRows`/`buildAdjustedAccBook` 수정이 뷰어·HWPX 서식7/22-x·결산·자료백업 .db에 일관 반영. `adjusted-ledger-parity`·`fund-realloc.test`(T15 등)·`settlement-summary` 회귀 갱신.
- **FR-6 (진짜 부족 표면화)**: 총액 부족 자금원/통장 부족은 0으로 숨기지 말고 기존 부족 경고(`shortfalls`) 체계로 표면화.

## 4. 설계 옵션 (Design에서 확정)

- **옵션 A — 원 자금원 잔류 스킵**: `useS`가 임계값 미만이고 부족분 전체를 단독 커버할 자금원이 있으면 원 자금원을 스킵(useS=0)하고 통째 이동. → **주의: 확성장치를 84→83으로 통째 옮기므로 "확성장치 84 유지" 위반**(사용자 반려한 방향). 단독으로는 부적합.
- **옵션 B — 이동 대상 선택 최적화 (유력)**: 자금원별 총 부족분을 먼저 계산하고, 그 부족분을 **통째 이동 가능한 지출들의 조합**으로 충당(부분합/근사). 확성장치는 이동 대상에서 보호하고, 로고송(663,800) 등 다른 통째 지출을 이동. → 자투리 0, 확성장치 84 유지. (부분합 선택 규칙·결정성 설계 필요.)
- **옵션 C — 총액 기준 + 통째 배정**: 시간순 as-of를 버리고 자금원별 총 부족분만큼만 통째 지출을 이동. 중간 잔액 음수 허용(FR-4). 가장 자투리 적으나 공식 형식 영향 큼.

**추천 검토 순서**: B(확성장치 보호 + 자투리 제거, 시간순 잔액 정책 영향 최소) → 필요 시 C.

## 6. 데이터 상태 (정상 — 정정됨)
- **통장 총잔액 0** (환급 #367 문자환급 −108,583 반영, 대시보드와 일치). 데이터 미완 아님, 수입 누락 없음.
- 구조: **84 −413,483 / 85 +413,483 상쇄**. 재배분이 84 부족을 85 잉여에서 충당하면 모든 자금원 잔액을 정합시킬 수 있다(진짜 부족·shortfall 없음).
- 집계 시 **환급(음수 지출) 반드시 포함**(`acc_amt !== 0`, `>0` 필터 금지) — [[negative-refund-rows-in-aggregation]].

## 7. 엣지 케이스
- 부족분을 정확히 맞추는 통째 지출 조합이 없을 때(부분합 실패) → 최소 분할로 폴백(자투리 최소화).
- 환급(음수 지출, [[negative-refund-rows-in-aggregation]]) 포함 시 총액 계산 부호.
- 통째 이동이 다른 자금원을 음수로 만들지 않는지(연쇄).
- 결정성: 이동 대상 선택이 시간/입력 순서에 결정적(Math.random 없음).

## 9. 결정 (확정) / 미해결

### 확정 (사용자)
- **D-1**: 지출 **과목(86/87)은 불변**, **자금원 이동은 가능**.
- **D-2**: **확성장치 540,000은 자금원 84 유지**(84 총수입 충분 전제). 자투리를 만드는 부분분할 대신 통째 이동 우선.
- **D-3**: 접근 = **확성장치 보호 규칙**(옵션 B 계열). 84 부족(413,483)은 85 잉여(413,483)로 충당 — 데이터 정상, 통장 0.

### 미해결 (Design)
- **OQ-1**: 소액 자투리 임계값(고정 원 vs 부족분 대비 비율).
- **OQ-2**: 자금원 잔액 정책 — 시간순 ≥0 유지 vs 총액 기준(중간 음수 허용). 공식 형식 정합.
- **OQ-3**: 이동 대상 선택 규칙(부분합/근사·우선순위·결정성).
- **OQ-4**: 84 부족분(413,483)을 85 잉여에서 충당할 때, 확성장치를 제외한 어느 84 지출을 통째 85로 옮길지(부분합 조합·결정성).
