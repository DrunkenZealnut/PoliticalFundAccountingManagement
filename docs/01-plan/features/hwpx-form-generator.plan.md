## Executive Summary

| 관점 | 내용 |
|------|------|
| **Problem** | 회계책임자는 선관위에 제출하는 약 56종의 한글(HWP) 서식을 매번 빈 양식에 수기로 옮겨 적는다. 조직 정보·거래내역·거래처 정보가 이미 시스템 DB에 있는데도 재입력해야 하며, 항목 누락·오기·서식 불일치 시 보완·반려 위험이 크다 |

| **Core Value** | 56종 서류 작성의 수기 부담과 휴먼에러를 제거하고, 시스템 DB ↔ 공식 제출서식을 직접 연결해 회계보고 워크플로우의 마지막 출력 단계를 완성한다 |

## 1. 배경 및 필요성

### 1.1 무엇을 만드나

사이드메뉴에 신규 항목 **"선관위 제출서류"**를 추가하고, 다음 흐름의 페이지를 제공한다.

```
[서식 카탈로그]  →  [서식 선택]  →  [입력 폼(자동 prefill + 수동)]  →  [미리보기/검증]  →  [.hwpx 다운로드]
```

생성 결과물은 한글(Hancom Office)에서 바로 열리는 **HWPX 파일**이며, 공식 서식 레이아웃(글꼴·표·셀 병합·여백)을 그대로 보존한다.

### 1.2 대상 서식 (약 56종)

`FORM_TEMPLATES.md` 기준 공식 서식 **45종** + 별지·부속서류 약 11종 = **약 56종**. 카테고리:

| 그룹 | 예시 서식 | 비고 |
|---|---|---|
| 인계·인수 | 1-1/1-2 정치자금 수입과 지출 인계·인수서(+별지) | 고정 레이아웃 |
| 회계책임자 | 2-1 선임신고서, 2-2 취임동의서, 2-3 약정서, 3 겸임, 6-1 변경 | 고정 레이아웃 |
| 계좌 | 4 예금계좌 신고서, 5 변경신고서 | 고정 레이아웃 |
| 회계장부 | 7/8 수입계정별 회계장부, 9 지출 위임장 | **표 행 가변** |
| 지출내역서 | 10/11/12-1/12-2/12-3/13 | 일부 표 행 가변 |
| 신고·신청 | 14 수당·실비 명세서, 15/16 이체, 17 증빙 정리, 18 이의신청 | 혼합 |
| 반환·마감 | 19 잔여재산 인계, 20 회계장부 마감, 21 지원금 반환 | 혼합 |
| 회계보고서 제출 | 22-x 후보자, 23-x 후원회 | 첨부 다수 |
| 후원회 운영 | 27 등록신청서, 28 정관, 29~36 운영서식 | 고정 레이아웃 |
| 영수증 관리 | 37~40 발급·반납·위임 | 혼합 |
| 보전·반환 | 41~45 국고귀속·보전청구·반환 | 일부 기존 Excel 기능 연계 |

> **수량 확정(부록 A)**: 작성예시 HWPX 실물 분석 결과 **목차 기준 53종**, 첨부서류(22-x 4종·23-x 11종 등) 확장 시 **작성예시 라벨 69개**. 사용자 표현 "56종"은 이 범위 내. 전체 목록은 **부록 A** 참조.

### 1.3 현재 시스템 Gap

- `submission-forms.ts`: 양식 메타데이터 카탈로그(약 22건)는 있으나 `generator`가 `print`/`page`/`excel`/`pdf`뿐 → **HWPX 생성 경로 없음**
- `package.json`: HWP/HWPX 의존성 **전무**(현재 Excel=ExcelJS, PDF=pdfjs-dist만)
- 사이드메뉴(`dashboard/layout.tsx` `MENU_ITEMS`)에 제출서류 통합 진입점 없음(서식 출력 `forms`는 별도 목적)
- 서식별 **입력 필드 정의**(어떤 항목을 DB로 채우고 어떤 항목을 사용자가 입력하는지)가 정의되어 있지 않음

### 1.4 왜 HWPX인가 (HWP 아님)

- 선관위 제출 관행상 한글 문서가 표준 → 사용자가 인쇄·날인·전자제출에 그대로 활용 가능
- `hwpx` 스킬은 **HWP(바이너리) 미지원, HWPX(ZIP+XML)만 지원**. 따라서 RAG의 `.hwp` 작성예시는 **한글에서 `.hwpx`로 재저장**해 템플릿화하는 선행 단계가 필수(결정사항 ③)

### 2.1 입력 폼 / 필드 정의 모델 (FR-02~04)

서식마다 입력 필드를 선언적으로 정의한다(신규 메타데이터):

```ts
// lib/hwpx/form-fields.ts (신규)
interface HwpxFormField {
  token: string;          // HWPX 템플릿의 {{token}}
  label: string;          // 화면 라벨
  type: "text" | "date" | "amount" | "regnum" | "select" | "textarea";
  source?:                // 자동 prefill 소스
    | { from: "organ"; column: string }
    | { from: "auth"; key: "orgName" | "acctName" | ... }
    | { from: "aggregate"; calc: "electionExpenseTotal" | ... };
  required?: boolean;
  editable?: boolean;     // prefill 후 사용자 수정 허용
}
interface HwpxFormDef {
  id: string;             // submission-forms.ts의 form id와 연결
  template: string;       // HWPX 템플릿 파일 경로/키
  fields: HwpxFormField[];
}
```

- **자동 prefill 소스**: `organ`(조직 정보), `auth` store(조직명·회계책임자명), `aggregate`(선거비용 합계 등 — 기존 `lib/accounting`·`excel-template/data-query` 재사용)
- **수동 보완**: `source` 없는 필드 또는 `editable: true` 필드는 폼에서 직접 입력/수정

### 2.2 HWPX 생성 파이프라인 (FR-05) — 핵심

```
HWPX 템플릿(.hwpx, {{token}} 포함)
   │  ① JSZip으로 in-memory unzip
   ▼
Contents/section0.xml (문자열)
   │  ② {{token}} → escapeXml(inputValue) 치환
   ▼
수정된 section0.xml
   │  ③ JSZip rezip (mimetype first, ZIP_STORED)
   ▼
result.hwpx (Buffer) → 브라우저 다운로드
```

- **런타임 의존성**: `jszip`(신규, Node/Vercel 호환). Python·lxml **불사용**(런타임 제약 회피)
- 구조(문단·표·스타일 ID)는 **건드리지 않고** 텍스트 노드만 치환 → 공식 레이아웃·쪽수 보존(hwpx 스킬 "치환 우선 편집" 원칙과 동일)

### 2.3 입력 검증 (FR-06)

- XML escape: `& < > " '` → 엔티티 (치환 전 필수, 미처리 시 HWPX 파손)
- 금액: 정수 원 단위, 천단위 콤마 표기 토큰 별도(`{{amount_won}}` 한글 금액 등)
- 날짜: `YYYY-MM-DD` 입력 → 서식별 표기(`YYYY년 MM월 DD일` 등)로 변환
- 필수 필드 미입력 시 다운로드 버튼 비활성 + 인라인 경고

## 6. 아키텍처 고려사항

### 6.1 프로젝트 레벨

기존 Next.js 16 + Supabase 앱에 페이지·API·lib 모듈을 추가하는 **Dynamic** 레벨 기능. 신규 인프라 불필요.

### 6.2 핵심 기술 결정

| 결정 | 선택지 | 선택 | 근거 |
|---|---|---|---|
| HWPX 생성 방식 | (A) 사전 템플릿 토큰 치환 / (B) XML-first 생성 / (C) Python 서버리스 | **(A)** | Vercel/Node 런타임에서 lxml 불가. 사전 제작 `.hwpx`에 토큰 치환 시 공식 레이아웃 100% 보존 + 의존성 최소(JSZip만) |
| 템플릿 원본 확보 | 사용자 `.hwpx` 변환 제공 / XML 신규작성 | **사용자 제공**(결정 ③) | `.hwp`→`.hwpx`(한글 재저장)이 공식 양식과 1:1. 내가 토큰 규칙·서식 목록 안내 |
| 템플릿 저장소 | `public/` 정적 / Supabase Storage | **Storage 우선**(public fallback) | 서식 추가·교체를 배포 없이 운영. 초기엔 `public/`로 시작 가능 |
| 데이터 채움 | DB 자동 + 수동 / 순수 수동 | **자동+수동**(결정 ①·②) | 입력 노력 최소화, 기존 data-query 재사용 |
| 생성 위치 | 서버 라우트 / 클라이언트 | **서버 라우트**(`/api/hwpx/generate`) | 템플릿 파일 접근·service-role 집계·바이너리 응답에 적합 |
| ZIP 라이브러리 | jszip / adm-zip / fflate | **jszip** | 브라우저·Node 양쪽 호환, mimetype-first 제어 용이 |

### 6.3 토큰 치환 안전 규칙(템플릿 준비 가이드 — 사용자 공유용)

1. 토큰은 `{{orgName}}` 형태로 **한 줄·한 스타일**로 입력(한글에서 서식 변화 없이 연속 타이핑) → `section0.xml`에서 한 `<hp:t>`에 보존되어 치환 가능
2. 토큰 사이에 자동 교정/서식 변경이 끼지 않도록 plain text로 작성
3. 표 셀 안의 토큰도 동일 규칙
4. 가변 길이 값(주소·비고)은 셀 폭을 넘기면 쪽수 드리프트 → 템플릿에서 충분한 셀 폭 확보(`page_guard.py`로 검증)
