# Plan — 수입·지출부 과목별 음수 잔액 제거 (Pass3 수입 재분류)

- 기능: `item-balance-pass3`
- 단계: Plan
- 작성일: 2026-06-26
- 유형: 후보자 회계 재배분(reallocation) SSOT 확장 (보고 시점, 원본 불변)
- 관련 메모: [[income-expense-item-allocation-persist]] · [[income-expense-book-funding-realloc]] · [[official-fund-data-income-classification]] · [[settlement-must-use-realloc-ssot]] · [[negative-refund-rows-in-aggregation]]

## Executive Summary

| 관점 | 내용 |
|------|------|
| **Problem** | 보고 시점 재배분(Pass2) 후에도 후보자 (계정×과목) 수입·지출부에서 한 과목이 **음수 잔액**으로 표시됨(실데이터: 오준석후보 후원회기부금 선거비용외 −5,007,485). Pass2의 시간순·FIFO 수입 충당 한계로, 수입이 들어온 과목과 지출 과목이 어긋나 한 과목 음수·다른 과목 양수로 분열. HWPX 서식7 등 선관위 제출 서식에 음수 잔액이 그대로 노출 |
| **Solution** | Pass2 직후 보고 시점 SSOT(`buildLedgerRows`)에 **Pass3** 추가 — 같은 자금원 내 **잉여 과목의 기존 수입을 음수 과목으로 '과목만' 재분류**해 음수 잔액을 0으로 제거. 가상 행 생성 없음, 수입 측만 변경(지출 과목 불변), 자금원별 합·통장 총잔액 불변. 진짜 통장 부족은 미적용·경고 유지 |
| **Function/UX** | 모든 산출물(수입·지출부 뷰어·HWPX 서식7/22-1·결산·자료백업 .db)에서 **과목 음수 잔액 제거** → 정상 데이터(자금원 총액 0)에선 같은 자금원 **모든 과목 잔액 0**. 자금원 총액이 0이 아니면(수입≠지출, 누락 지출 등 데이터 미완) plug로 숨기지 않고 **경고로 표면화** |
| **Core Value** | 선관위 제출 서식 정합(과목 음수 잔액 0) + 원본 acc_book 불변·합 보존 + 실제 잔여금/데이터 오류는 숨기지 않는 회계 정직성 |

## 1. 배경 / 문제

### 1.1 현상
후보자 수입·지출부는 (계정×과목)별 시트로 출력된다. 보고 시점 재배분(`buildAdjustedAccBook` = Pass0→1→2)을 거쳐도 **특정 과목의 마지막 누계 잔액(= 누계수입 − 누계지출)이 음수**로 남을 수 있다. 음수 잔액은 "그 과목에서 받은 돈보다 더 썼다"는 뜻이라 회계상 성립하지 않으며, 선관위 제출 서식(특히 HWPX 서식7 회계장부, 22-4 수입·지출부)에 그대로 찍히면 안 된다.

### 1.2 실데이터 (2026 오준석후보, 후원회기부금 acc_sec_cd=85)
| 과목 | 수입 | 지출 | 잔액 |
|------|-----:|-----:|-----:|
| 선거비용 (86) | 9,430,000 | 4,290,015 | **+5,139,985** |
| 선거비용외 (87) | 0 | 5,007,485 | **−5,007,485** |
| **85 합계** | 9,430,000 | 9,297,500 | **+132,500** |

> **핵심(사용자 확인 완료)**: 정상 데이터에서 후원금(85) **총액은 0**이어야 한다(132,500원은 실제 지출분 — 이 스냅샷 `.db`에는 해당 지출이 누락돼 +132,500으로 보임). 즉 총액이 0이면 재분류(Pass3)로 **선거비용외(87) −5,007,485 → 0, 선거비용(86) → 0** 둘 다 0이 된다. 총액이 0이 아닌 스냅샷은 **누락 지출(데이터 미완) 신호**이므로 plug로 메우지 않고 경고로 표면화하고, 데이터가 보완되면 자동으로 0이 된다(D-3·FR-3).

### 1.3 근본 원인 (조사 결과)
- 재배분 SSOT: `lib/accounting/ledger-allocation.ts` `buildLedgerRows` = Pass0(`adjust-negative-income`) → Pass1(`fund-realloc` 자금원 음수 해소, 지출만 이동) → Pass2(`item-allocation` 수입을 지출 과목으로 재태깅).
- Pass2(`item-allocation.ts allocateOneSource`)는 자금원별로 시간순 처리하며, 지출(과목 M) 충당 시 **그 시점에 이미 도착한(시간상 먼저인) 수입 슬라이스만** 다른 과목 풀에서 끌어올 수 있다(`drawFromPool`). 부족분이 남으면 **그 지출은 원과목 유지 → 음수 표면화**(의도된, 은폐 금지 동작).
- 즉 Pass2는 과목 균형을 **best-effort**로만 맞추고, **잔액 음수를 제거하는 Pass가 없다.** 본 기능이 그 마지막 Pass3를 추가한다.
- 원본 불변 원칙: 모든 재배분은 **보고 시점 메모리에서만** 일어나고 원본 `acc_book`은 불변(`adjusted-ledger.ts` 헤더, scripts/018이 영구화 컬럼/RPC를 DROP). Pass3도 동일하게 보고 시점 순수 함수.

## 2. 목표 / 비목표

### 2.1 목표 (Goals)
- 후보자 (계정×과목) 수입·지출부에서 **과목 음수 잔액을 0으로 제거**한다(재분류).
- 모든 보고 산출물에 일관 반영(SSOT 한 곳 수정).
- 원본 acc_book 불변, 자금원별 수입합·지출합·통장 총잔액 **불변**.
- 실제 잔여금·진짜 통장 부족(데이터 오류)은 **은폐하지 않는다**.

### 2.2 비목표 (Non-goals)
- 원본 acc_book 데이터 수정(영구화) — 하지 않음(보고 시점만).
- 지출 과목·금액 변경 — 하지 않음(수입 측만 재태깅, 불변식 L7/L8 유지).
- 비후보자(후원회 1/2 인코딩) 처리 — 본 건은 후보자(82~85)만.
- 자금원 간 이동(그건 Pass1의 일) — Pass3는 **같은 자금원 내 과목 간**만.
- 진짜 통장 부족(총지출>총수입)을 0으로 가리기 — 하지 않음(D-3).

## 3. 기능 요구사항 (FR)

- **FR-1 (Pass3 추가)**: `buildLedgerRows`에서 Pass2 직후, 자금원별로 (effectiveItemSecCd) 순잔액(수입−지출)을 계산해 **음수 과목 M(부족 D)**에 대해 **잉여 과목 N의 기존 수입 슬라이스를 D만큼 과목 M으로 재태깅**(`effectiveItemSecCd` N→M)한다. 새 행 생성 없이 기존 수입 슬라이스의 과목만 변경(필요 시 슬라이스 분할은 기존 `item-allocation` 관례 재사용: spread 복제 + 신규 id + note).
- **FR-2 (총액 0 → 모든 과목 0)**: 자금원 총액(수입합−지출합)이 0인 정상 데이터에서, 음수 과목의 부족분을 잉여 과목의 기존 수입으로 메워 **같은 자금원 모든 과목 잔액을 0**으로 만든다. (총액 0이므로 음수 제거 = 양수 과목도 0이 됨. 사용자 예시 의도와 동일.)
- **FR-3 (총액≠0은 plug 금지·표면화)**: 자금원 총액이 0이 아니면(수입>지출 잔여 **또는** 총지출>총수입 부족) Pass3로 0을 **강제하지 않는다**. 누락 지출/데이터 미완 신호이므로 plug로 메우거나 숨기지 않고, 기존 부족 경고(`detectCandidateShortfalls`, `shortfall-surface`) 체계로 **표면화**한다(수입 초과 잔여도 동일하게 경고 대상으로 확장). 데이터가 보완돼 총액이 0이 되면 FR-2가 자동 적용. (은폐 금지)
- **FR-4 (불변식 보존)**: ① 지출 과목/금액 불변(수입 측만) ② 자금원별 수입합·지출합 불변 ③ 통장 총잔액 불변 ④ 후보자(82~85)만. → Pass1/Pass2 기존 회귀(L7/L8)와 충돌 0.
- **FR-5 (전 산출물 반영)**: SSOT `buildLedgerRows` 수정으로 수입·지출부 뷰어 · HWPX 서식7/22-4 · 회계보고서 22-1 · 결산 · 자료백업(.db) export가 **자동 일관** 반영. 회귀 테스트로 고정.
- **FR-6 (영수증 채번 무해)**: 재태깅된 수입은 [[income-receipt-no-omitted]]로 **이미 "생략"** 표기되므로 영수증번호 영향 없음(plug 행이 아니라 재태깅이라 신규 채번 행도 없음).

## 4. 설계 스케치 (Design 단계에서 확정)

```
buildLedgerRows(rows):
  p0 = adjustNegativeIncome(rows)           # Pass0 (기존)
  p1 = reallocateFundSources(p0).rows       # Pass1 자금원 (기존)
  p2 = allocateIncomeToItems(p1)            # Pass2 과목 best-effort (기존)
  p3 = zeroNegativeItemBalances(p2)         # Pass3 (신규) ← 본 기능
  return p3
```

`zeroNegativeItemBalances` (순수 함수, 신규 `lib/accounting/item-balance-zero.ts` 가칭):
- 자금원(계정 82~85)별로 그룹.
- 자금원 **총액(수입합−지출합) ≠ 0**이면 skip + 경고 표면화(FR-3). (총액 0일 때만 진행)
- effectiveItemSecCd별 순잔액 계산 → 음수 과목 M(부족 D), 양수 과목 N(잉여).
- N의 잔여 수입 슬라이스에서 D만큼을 과목 M으로 재태깅(결정적 순서, OQ-2/3). 합 보존.
- 결과: 총액 0이므로 **모든 과목 0**(M=0, N도 0).

**적용 레이어**: `ledger-allocation.ts buildLedgerRows`(SSOT, 보고 시점). `item-allocation.ts`의 자료구조(과목 풀/슬라이스)를 재사용하거나 별도 후처리 패스로 분리.

## 6. 엣지 케이스
- 자금원에 음수 과목이 여러 개 / 양수 과목이 여러 개 → 결정적 매칭 순서 필요(과목 코드 순 등).
- 양수 과목 잉여 < 음수 과목 부족(자금원 합 < 0, 진짜 부족) → FR-3로 skip(경고 유지).
- 환급(음수 지출, [[negative-refund-rows-in-aggregation]]) 포함 시 순잔액 계산이 `acc_amt` 부호를 정확히 반영하는지.
- 비후보자/후원회 데이터 → 적용 안 함(buildAdjustedAccBook이 이미 후보자만).
- Pass3 재태깅이 Pass2의 슬라이스/`alloc` 메타와 충돌하지 않는지.

## 8. 결정 (확정) / 미해결

### 확정된 결정 (사용자 승인)
- **D-1 구현 방식**: 기존 수입 **재분류(Pass3)** — 가상 plug 행 추가 안 함. (선관위 제출물에 없던 거래를 만들지 않음, 합·통장잔액 불변)
- **D-2 적용 범위**: **모든 보고 산출물**(SSOT 한 곳 수정으로 뷰어·HWPX·22-1·결산·.db 일관).
- **D-3 진짜 부족 시**: **0 강제 안 함** — 과목만 분열(합≥0)인 경우에만 적용, 진짜 통장 부족은 부족 경고 유지(은폐 금지).

### 확정된 결정 (사용자 승인) — 추가
- **D-4 (총액 0 전제)**: 정상 데이터에서 자금원 총액은 0(132,500은 실제 지출분). 따라서 재분류만으로 모든 과목 0이 되며, **plug/가상 행 불필요**(D-1 재분류로 충분). 총액이 0이 아닌 스냅샷은 **누락 지출(데이터 미완)**이므로 0 강제 금지·경고 표면화(FR-3). → OQ-1 종결.

### 미해결 (Design에서 확정)
- **OQ-2**: 음수/양수 과목이 다대다일 때 재태깅 매칭 순서(과목 코드 순 / 금액 순 / 시간순).
- **OQ-3**: 양수 과목이 둘 이상이면 어느 과목에서 우선 끌어올지(예: 선거비용외 부족분을 선거비용에서만? 비례 배분?).
- **OQ-4**: 결산확정(`finalize_settlement`)·잔액검증(현금및예금)과의 상호작용 재확인(통장 총잔액 불변이라 영향 없을 것으로 예상하나 명시 검증).

## 9. 리스크
- **회계/법적 민감성**: 수입 과목 재분류는 "어느 후원금이 어느 비용에 쓰였나"의 분류 변경. 기존 Pass2가 이미 하는 일의 연장이라 정당하나, 선관위 제출 서식에 반영되므로 Design에서 회계 정당성 문구·근거를 명확히.
- **데이터 미완 은폐 위험**: 자금원 총액이 0이 아닌데(누락 지출 등) plug로 0을 강제하면 데이터 오류가 가려짐 → **총액 0일 때만 재분류, 총액≠0은 경고 표면화**(FR-3) 고수.
- **SSOT 광범위 영향**: buildLedgerRows 한 곳 수정이 6개 산출물에 전파 → parity/회귀 테스트 필수.
