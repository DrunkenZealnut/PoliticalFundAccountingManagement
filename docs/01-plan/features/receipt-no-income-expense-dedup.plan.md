## Executive Summary

| 관점 | 내용 |
|------|------|
| **Problem (문제)** | 재조정 데이터 뷰어(`income-expense-book`)의 수입·지출부에서 **영수증일련번호가 20건 중복**된다. ① 지출엔 수기 번호(`자(비)-1`…)가 있으나 **수입은 원본에 번호가 없어**, 보고 시점 자동채번이 같은 접두사를 1부터 다시 매겨 수입↔지출이 충돌(15건). ② 자금원 재배분으로 **이동된 분할 조각이 원본 영수증번호(접두사)를 그대로** 물려받아 자기 계정과 안 맞는 번호가 됨(5건). |
| **Solution (해결)** | 보고/백업 채번(`fillExportReceiptNumbers`)을 **`incm_sec_cd` 분리 스코프 → 수입·지출 통합 단일 스코프**로 전환하고, 각 행의 **현재 (계정×과목) 접두사 기준으로 채번**한다. 수기 지출번호는 보존(접두사 일치분), 수입·이동조각은 해당 접두사 max+1부터 이어서 부여 → 중복 0, 접두사–계정 정합. |
| **Function UX Effect (기능·UX 효과)** | 통합 수입·지출부·자료백업(.db)의 영수증일련번호가 한 컬럼에서 **고유**해지고, 재배분된 행도 자기 자금원 접두사(`자(비)`/`외(비)`)를 갖는다. 윈도우 선관위 프로그램·제출서류의 일련번호 신뢰성 확보. |
| **Core Value (핵심 가치)** | 법정장부(수입·지출부)의 영수증 식별성·추적성 회복 — 같은 번호가 두 거래를 가리키는 모순 제거. |

## 2. 분석 — 근본 원인 (실데이터 재현 확정)

### 원본 데이터 사실 (org_id=11, 2026-02-19~06-23, 73행)
- **지출(incm=2) 55행 = 전부 rcp_no 보유**(수기, `자-1·자(비)-1..21·후(비)-1..21·후-1..8·외(비)-1`). 지출 내부엔 중복 없음.
- **수입(incm=1) 18행 = 전부 rcp_no 없음(null)**.

### RC1 — 수입↔지출 접두사 충돌 (15건)
`fillExportReceiptNumbers`(`receipt-no.ts:164-198`)가 `incm_sec_cd`별로 그룹을 나눠(`byIncm`) 각 그룹의 `existing`/`targets`를 **독립** 처리한다. 수입 그룹의 `existing`는 비어 있어(수입 원본 번호 0건) 수입 자동채번이 `자(비)-1, 후(비)-1, 외(비)-1…`을 **1부터** 만들고, 기존 지출 수기번호와 충돌.

| 충돌 영수증번호(예) | 수입 행 | 지출 행 |
|---|---|---|
| `자-1` | 후보자자산 6,500,000 | 보증금 3,000,000 |
| `자(비)-1` | 예금이자 57 | 점퍼 95,000 |

| …(총 15) | | |

### Finding 3 검증 결과 — 분할은 버그가 아님 (재배분 필수)
"같은 과목 분할" 의혹은 **Pass1 자금원 재배분(음수잔액 해소, 불변식 I2)** 으로 확정. 원본 기준 자금원별 시간순 잔액 검증:

```
83 보조금외   : 최저 0 (OK)
84 후보자자산 : 최저 0 (OK)
85 후원회기부금: 최저 -873,960 @20260531 ⚠️ 음수
```

후원회기부금은 후원금이 **06/01·06/02에 늦게 입금**되는데 지출이 05/22~05/31에 선행 → 5/22 인형탈대여부터 통장이 마이너스. 재배분이 이 부족분을 잔액 있는 84·83으로 옮겨 (계정×과목) 잔액 음수를 막는다(공식 Fund_Data 구조와 동일). **재배분 로직은 그대로 두는 것이 정답**이며, 손볼 것은 RC2(이동 조각 접두사)뿐이다.

## 3. 변경 방향 (제안)

### 3.1 핵심 — `fillExportReceiptNumbers` 통합 스코프 채번
`incm_sec_cd` 분리 제거 → **전 행 단일 스코프**, 접두사는 각 행의 현재 `formatKey`(계정/과목) 기준:

1. **보존(existing, 접두사 max 산출에 기여)**: `rcp_no`가 있고 **접두사 == `formatKey(현재행)`** 인 행 (이동 안 한 수기 번호). → 지출 `자(비)-1..21` 등 그대로 유지.
2. **채번(targets)**: `rcp_yn='Y'` 이면서 (`rcp_no` 없음 **또는** 접두사 ≠ `formatKey(현재행)`[이동조각 stale]). → 수입 18행 + 이동조각.
3. 접두사별 순번 = 해당 접두사 existing max + 1부터, 정규 정렬(`acc_date → 수입먼저 → acc_book_id`)로 부여. `rcp_no2`(정수)는 전체 고유 순번 유지.

**예상 결과**:
- 지출 `자(비)-1..21`·`후(비)-1..21`… 보존.
- 수입 자산행 → `자(비)-22`·`자-…`(max 이어서), 후원회수입 → `후(비)-22…`. 수입↔지출 충돌 0.
- 인형탈 이동조각 84→`자(비)-N`, 83→`외(비)-N`. 접두사–계정 정합, 중복 0.

## 4. 핵심 결정 사항 (Design 단계 확인 필요)

> **D-1. 이동 분할 조각의 영수증번호** — 한 물리 영수증(예 인형탈 `후(비)-10`)이 3계정으로 쪼개질 때:
> - **(A) 각 조각에 계정 접두사 부여** `후(비)-10`/`자(비)-N`/`외(비)-N` — 접두사–계정 정합, 모든 행 고유. *(권장 — 사용자가 고른 "통합 연번"과 정합, 자금원별 식별)*
> - (B) 세 조각이 원 영수증번호 공유 — "한 영수증=한 번호" 보존, 단 접두사 stale 잔존.
>
> 사용자 1차 답변("수입·지출 통합 연번")은 **(A)** 방향으로 해석. Design에서 최종 확정.
