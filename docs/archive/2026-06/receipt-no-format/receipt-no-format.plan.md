### Value Delivered (4-Perspective)

| Perspective | 내용 |
|---|---|
| **Problem** | 영수증 일련번호 표시값(`rcp_no`)이 선관위 공식 예시와 불일치한다. (1) 후보계정 **선거비용외**가 `자(비외)-1`로 생성되나 공식 예시는 `자-1`(괄호 없음). (2) **후원회계정 지출**은 전용 규칙이 없어 계정 첫글자 폴백으로 `후(후)-1`·`기(기)-1` 같은 비표준 값이 나오나, 공식 예시는 과목 약자만 쓴 `기-1·모-1·인-1·사-1·그-1`이다. 잘못된 영수증번호로 백업(.db)을 만들면 선관위 윈도우 프로그램의 수입·지출부 영수증일련번호가 어긋난다. |

| **Function/UX Effect** | 「영수증 일괄생성」 및 자료백업(export-sqlite) 모두에서 후보 선거비용외는 `자-1`, 후원회 지출은 `기-1`처럼 공식 예시와 동일한 번호가 부여된다. 사용자가 출력·제출하는 수입·지출부의 영수증일련번호가 선관위 양식과 1:1 일치한다. |
| **Core Value** | 영수증 일련번호가 **선관위 공식 표기 규칙**을 준수하여, 회계장부·백업파일·제출서류 전반의 표기 신뢰성이 확보된다. |

## 개요

영수증 일련번호 표시값(`rcp_no`)의 채번 규칙을 사용자가 새로 제시한 선관위 공식 예시 2종(후보계정·후원회계정)에 맞춰 개정한다. 채번 로직 SSOT는 `app/src/lib/accounting/receipt-no.ts`이며, 두 소비처(앱 「영수증 일괄생성」 = `api/acc-book` batch_receipt, 자료백업 = `api/system/export-sqlite` `fillExportReceiptNumbers`)가 이 SSOT를 공유한다. 따라서 SSOT만 정확히 고치면 두 경로가 동시에 교정된다.

## 새 채번 규칙 (목표 사양)

### 영역 A — 후보계정 (자금원 계정 4분류 × 과목)

| 구분(계정) | 선거비용 | 선거비용외 |
|---|---|---|
| 자산(84) | `자(비)-1` | `자-1` |
| 후원회기부금(85) | `후(비)-1` | `후-1` |
| 보조금(82) | `보(비)-1` | `보-1` |
| 보조금외(83) | `외(비)-1` | `외-1` |

- 계정 약자: 84→자, 85→후, 82→보, 83→외 (**현행 `ACC_ABBR` 유지**).
- **선거비용** 과목: `{계정약자}(비)-n` — **현행 유지**.
- **선거비용외** 과목: `{계정약자}-n` — **변경**(현행 `{계정약자}(비외)-n`에서 `(비외)` 괄호 **완전 제거**).
- 수입·지출 동일 형식(과목이 선거비용/선거비용외인지로만 결정). incm_sec_cd별 순번 독립은 현행 유지.

### 영역 B — 후원회계정 지출

| 구분(지출 과목) | 영수증번호 |
|---|---|
| 기부금 | `기-1` |
| 후원금모금경비 | `모-1` |
| 인건비 | `인-1` |
| 사무소설치운영비 | `사-1` |
| 그밖의경비 | `그-1` |

- 형식: `{과목약자}-n` — **계정약자 없음, 괄호 없음**.
- 과목 약자 매핑(확정): 기부금→`기`, 후원금모금경비→`모`(첫글자 '후' 아님 — **명시 매핑 필요**), 인건비→`인`, 사무소설치운영비→`사`, 그밖의경비→`그`.
- 적용 조건: 후원회 org(ORG_SEC_CD=109)의 **지출**(incm_sec_cd=지출) 행에만 적용.

### 영역 C — 후원회 수입 · 기타 (현행 유지)

- 후원회 **수입**은 채번 규칙을 변경하지 않는다(사용자 확정: "현행 유지").
- 후보/후원회 외 미정의 계정도 현행 폴백 유지.

## 현행 vs 목표 (코드 관점)

| 위치 | 현행 | 목표 |
|---|---|---|
| `itemAbbr("선거비용외…")` | `"비외"` | (영역 A) 후보 선거비용외는 괄호 자체를 생략 → `formatKey`에서 빈 과목 처리 |
| `formatKey()` | 항상 `{a}({i})` | 계열별 분기: 후보 선거비용 `{a}(비)`, 후보 선거비용외 `{a}`, 후원회 지출 `{과목약자}` |
| 후원회 지출 과목 약자 | 첫글자 폴백(후원금모금경비→'후') | 명시 매핑(→'모') |
| 후원회 수입/기타 | 첫글자 폴백 | 유지 |

## 설계 방향 (Do 단계에서 구체화)

핵심은 `formatKey(t, codeNames)`가 **행의 계정 계열을 판정**해 3-스킴 중 하나를 선택하도록 하는 것이다. 판정 입력은 행이 이미 보유한 `acc_sec_cd`·`item_sec_cd`·(필요 시)`incm_sec_cd`와 코드명이다.

1. **후보 자금원 계정 판정**: `acc_sec_cd ∈ {82,83,84,85}` (또는 `FUNDING_SOURCE_BY_ACC_SEC_CD` 재사용).
   - 과목명이 "선거비용외" 포함 → `{계정약자}` (괄호 생략).
   - 과목명이 "선거비용" 포함 → `{계정약자}(비)`.
   - 그 외(후보 수입 과목 등) → 현행 폴백.
2. **후원회 지출 판정**: 후보 계정이 아니고 지출 과목이 후원회 5분류에 해당 → `{과목약자}`(명시 매핑).
3. **그 외(후원회 수입·기타)**: 현행 `{a}({i})` 폴백 유지.

> **Do 단계 선결 확인사항**: 후원회 5개 지출 분류(기부금/후원금모금경비/인건비/사무소설치운영비/그밖의경비)가 `acc_sec_cd`(계정)인지 `item_sec_cd`(과목)인지 실제 codeset에서 확정한다. 약자 매핑은 cv_id가 아닌 **코드명 기준**(예: 코드명에 "모금" 포함 → '모')으로 작성해 코드 ID 변동에 견고하게 한다. `incm_sec_cd`가 함수에 전달되는지 확인(현재 `assignReceiptNumbers`의 `ReceiptTarget`엔 없음 → 후원회 수입/지출 구분이 필요하면 타입 확장 또는 과목 코드만으로 판정).

## 리스크 / 엣지 케이스

- **선거비용외 괄호 제거 후 키 충돌**: 후보 선거비용외 키 `자`와 후원회 지출 키가 약자상 겹치지 않는지(후원회는 기/모/인/사/그). 조합별 순번은 incm 스코프 내 키 기준이라 후보/후원회는 계정 계열 분기로 분리됨 → 충돌 없음 확인 필요.
- **full 모드 혼합 export**: `fillExportReceiptNumbers`는 incm_sec_cd로만 그룹화 → 한 그룹에 후보·후원회 지출이 섞일 수 있음. 키가 다르므로 조합 순번은 분리되나, 의도대로 분리되는지 테스트로 고정.
- **후원금모금경비 약자**: 첫글자 폴백('후')과 다른 '모' — 명시 매핑 누락 시 회귀. 테스트로 가드.
- **기존 부여분 보존**: `existing` max+1 이어가기 로직은 유지. 규칙 변경 후 신규/기존 혼재 시 순번 연속성 확인.
- **SSOT 단일화**: `income-expense-book.ts`의 별도 재구성 로직이 SSOT와 어긋나면 출력 불일치. 가능하면 SSOT 함수 재사용으로 통일(범위는 Do에서 판단).

## 범위 밖 (YAGNI)

- 이미 부여된 과거 데이터의 `rcp_no` **소급 재채번**은 하지 않는다(미부여분·신규분에만 적용; 필요 시 별도 작업).
- 후원회 수입 채번 규칙 변경(사용자 확정: 현행 유지).
- 영수증번호 외 다른 표기(과목명/계정명 라벨) 변경 없음.
