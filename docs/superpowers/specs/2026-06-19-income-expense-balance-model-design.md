# 정치자금 수입·지출부 — 올바른 잔액 모델 설계

- 작성일: 2026-06-19
- 상태: 설계 확정 (구현 전)
- 영향: `income-expense-book/page.tsx`, `reports/page.tsx`, `lib/hwpx/income-ledger-builder.ts`(서식7)

## 1. 문제

정치자금 수입·지출부를 **계정(자금원)×과목(선거비용/선거비용외)별**로 출력할 때 잔액이 깨진다.

- **원래 동작(v0.14.8.0, 현재 프로덕션)**: 수입·지출을 모두 과목으로 필터. 선거비용외(과목 87)로 뽑으면 잔액이 **음수**(org 11: −5,038,525). 선거비용외를 충당한 수입이 과목 86으로 기장돼 87 슬라이스에 수입이 모자라기 때문.
- **Option B(v0.15.0.0, revert됨)**: "수입=자금원 전체, 지출=선택 과목"으로 음수는 막았으나 무관한 거액 수입까지 합산돼 잔액이 **부풀려짐**(org 11: 22,993,867). 폐기.

두 시도 모두 증상이다. 근본 원인은 **수입의 과목 태깅**이다.

## 2. 근거 — 공식 프로그램 모델 (Fund_Data_1.db)

선관위 공식 프로그램의 후보자 데이터 파일을 분석한 결과:

- `ACC_BOOK`에 **잔액 컬럼이 없다**(렌더 시 계산). `SUM_REPT`(집계)도 비어 있다.
- 20개 거래에서 **모든 (계정×과목) 조합이 정확히 균형(잔액 0)**:
  - 보조금×선거비용 2,320,000=2,320,000, 보조금×선거비용외 1,680,000=1,680,000
  - 후보자자산×선거비용 1,379,500=1,379,500, 후보자자산×선거비용외 420,000=420,000
- 비결: **수입을 "충당 대상 과목"으로 기장**한다. 예) 후보자자산×선거비용외에서 수입 "후보자 자산" 420,000을 과목 87로, 지출 "기탁금" 420,000도 과목 87로. 수입 과목이 지출 과목과 맞아떨어져 슬라이스해도 균형.

→ **공식 모델 = (계정×과목)별 장부 + 수입을 충당 과목으로 기장.** 우리 데이터는 수입 과목이 잘못 기장(대부분 86)돼 깨진다.

## 3. 결정 (확정)

- **교정 위치**: 출력 시 **자동 배분(표시용)**. 원본 `acc_book` 불변, 데이터 마이그레이션 없음. (사용자 결정)
- **잉여 수입**(자금원 수입 > 지출): **원래 과목 그대로 유지**. (사용자 결정)
- 적용 범위: **후보자 기관(`orgType==="candidate"`)만**. 후원회/정당 등은 자금원/과목 개념이 달라 종전 동작 유지.

## 4. 모델 — 표시용 2-pass 배분

실데이터 검증으로 **두 차원 모두** 깨질 수 있음을 확인:
- 자금원 단독 음수: org 9 계정 82(−1,866,665), 계정 85(−1,129,000) → 자금원 재배분 필요
- (계정×과목) 음수: org 11 계정85×87(−5,007,485) → 과목 배분 필요

### Pass 1 — 자금원 재배분 (기존 `lib/accounting/fund-realloc.ts` 재사용)

지출을 시간순으로 훑어, 한 자금원의 가용액을 초과하는 지출분을 수입이 남는 다른 자금원으로 분할 이동(`reallocateFundSources`). 결과: **모든 자금원의 시간순 현금잔액 ≥ 0**.

### Pass 2 — 과목 배분 (신규 `lib/accounting/item-allocation.ts`)

Pass 1 결과(자금원이 확정된 행)를 받아, **각 자금원 내부에서 수입을 과목에 배분**한다. fund-realloc이 "지출을 자금원 간 이동"이라면, 이건 "수입을 과목 간 이동"으로 대칭.

규칙(시간순, 최소 이동):
1. 각 자금원의 행을 시간순 정렬(`compareAccDateTime`, 동시각 수입 먼저).
2. 과목별 가용 수입 풀을 유지. 수입 행 → 해당 과목 풀에 적립(원래 과목 기준).
3. 지출(과목 M) 발생 시 과목 M 풀에서 차감. **부족하면** 잉여가 있는 다른 과목 풀에서 **부족분만큼** 수입을 끌어와 과목 M으로 재태깅(수입 행 분할).
4. 어느 지출도 충당하지 않고 남은 수입(잉여) → **원래 과목 유지**(결정사항).

**조합 보장**: Pass 1로 자금원 현금이 항상 ≥0 → 과목 전체 합으로는 수입이 지출을 항상 덮음 → Pass 2에서 끌어올 잉여가 항상 존재 → **모든 (계정×과목) 잔액 ≥ 0** 이며, 충당된 만큼 균형(공식 구조와 일치).

### 출력 행 형태

각 출력 행은 다음을 보유(표시·필터·집계용):
- `sheetAccSecCd` — 배치될 자금원(Pass1 결과)
- `effectiveItemSecCd` — 배분된 과목(Pass2 결과; 수입은 분할로 원래≠배분 가능, 지출은 원래 과목 유지)
- `effectiveAmt` — 분할 후 금액
- `origin`/`note` — 분할·이동 추적(비고 표기용)

## 5. 컴포넌트 / 인터페이스

- `lib/accounting/item-allocation.ts` (순수, 단위 테스트):
  - `allocateIncomeToItems(rows: AllocRow[]): AllocOutRow[]` — 한 자금원 집합을 받아 과목 배분. 또는 전체를 받아 자금원별로 그룹핑 후 처리.
- `lib/accounting/ledger-allocation.ts` (조합 헬퍼, 순수):
  - `buildLedgerRows(rows): LedgerOutRow[]` = `reallocateFundSources` → `allocateIncomeToItems`. 페이지/빌더가 이 한 함수만 호출.
- 연결(후보자만, 표시용):
  - `income-expense-book/page.tsx`: 전 기간 조회 → `buildLedgerRows` → 선택 계정/과목 필터(수입·지출 모두 `effectiveItemSecCd`로 필터하면 음수 없음).
  - `reports/page.tsx`: `buildLedgerRows` 후 (sheetAccSecCd, effectiveItemSecCd) 조합으로 시트 구성.
  - `lib/hwpx/income-ledger-builder.ts`: 그룹 키를 `effectiveItemSecCd` 기준으로.

비후보자 경로는 `buildLedgerRows`를 거치지 않고 원본 사용.

## 6. 가드 / 엣지 케이스

- **환급(음수 지출)**: fund-realloc은 원 자금원 가용 복원(재배분 안 함). 과목 배분도 음수 지출은 그대로(해당 과목 잔액 복원).
- **잔액 미입력 자금원/과목**: 빈 양식 유지(기존 standardCombos 패턴).
- **익명·영수증 등**: 분할 행은 원본 메타 보존, `effectiveAmt`만 분할.
- **0원 거래**: 제외(기존 규칙).
- **shortfall(통장 전체 부족)**: Pass1에서 발생 시 원 자금원 음수 잔류(기존 동작). 현실 단일계좌에선 미발생 가정.

## 7. 검증 (구현 시 필수)

1. **공식 구조 재현**: Fund_Data_1.db의 20거래를 입력하면 모든 (계정×과목) 잔액 0(현재 이미 균형이므로 배분이 항등에 가깝게 동작).
2. **실데이터 무음수**: org 9·11에서 `buildLedgerRows` 후 모든 (계정×과목) 시간순 최저잔액 ≥ 0, 부풀림 없음.
3. **합 보존**: 과목 배분 후 자금원별 수입 합 = 원본 수입 합, 지출 합 = 원본 지출 합(분할만, 증발/증식 없음).
4. **단위 테스트**: item-allocation 시간순/분할/잉여-원과목/환급 케이스. fund-realloc과의 조합 불변식.
5. **회귀**: 비후보자 기관은 종전 동작 유지(스냅샷/필터 동일).
