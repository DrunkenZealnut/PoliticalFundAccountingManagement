# 증빙 PDF 배송비 감지 → 별도 등록 안내

- 작성일: 2026-06-06
- 상태: 설계 승인됨 (구현 계획 대기)

## 1. 배경 / 문제

증빙(견적서·영수증) 안에 제작비/물품비와 **배송비(운송·발송·택배·포장발송비)** 가 한데 묶여
있는 경우, 사용자가 이를 한 줄로 합산 등록하면 회계 항목 구분이 흐려진다. 실제 사례:
점자공보물 견적서(합계 361,000원)는 제작비 316,800원과 "박스/포장/발송비" 44,352원이
한 견적서에 있으나, 두 건의 지출로 분리 등록되어야 한다.

증빙 업로드 시 배송비 포함 여부를 감지해 **"배송비는 별도 항목으로 등록하라"** 고
사용자에게 안내한다.

## 2. 범위 / 제약 (합의된 결정)

- **감지 대상: PDF 텍스트 레이어만.** 전자 견적서·전자 영수증(텍스트 PDF)은 감지하고,
  사진/스캔 이미지(JPG·PNG)는 텍스트가 없으므로 검사하지 않고 조용히 통과한다.
  (이 프로젝트는 OCR/AI 추출을 쓰지 않는다는 기존 원칙 유지.)
- **안내 형태: 인라인 경고 배너.** 비차단 — 사용자는 무시하고 거래를 저장할 수 있다.
  이미 배송비를 별도 등록한 경우에도 흐름을 막지 않는다.
- **자동 분개/자동 항목 생성은 하지 않는다.** 안내(리마인더)까지만 한다. (YAGNI)

## 3. 동작 흐름

1. 사용자가 증빙 파일을 첨부한다 (`EvidenceFileManager.handleSelect`).
2. 첨부 파일이 PDF면 텍스트 레이어를 추출한다.
3. 추출 텍스트에서 배송비 키워드를 검사한다.
4. 감지되면 증빙 영역 상단에 노란 인라인 경고 배너를 표시한다:
   > ⚠️ 이 증빙에 배송비(운송·발송·택배 등)가 포함된 것 같습니다.
   > 배송비는 별도 항목으로 등록하세요.
5. 사용자는 배너를 무시하고 거래를 저장할 수 있다. 파일을 제거하면 배너도 사라진다.

## 4. 구성 (단위 분리)

| 단위 | 역할 | 의존 | 위치 |
|---|---|---|---|
| `detectDeliveryFee(text)` | 순수 함수. 텍스트 → `{ matched: boolean, keyword?: string }`. 단위 테스트 대상 | 없음 | `lib/evidence/delivery-fee-detector.ts` |
| `extractPdfText(base64)` | pdfjs-dist로 PDF 텍스트 추출 (I/O, 클라이언트 동적 import) | pdfjs-dist | 같은 모듈 |
| 배너 UI + state | 첨부 시 PDF면 추출→감지 호출, `deliveryWarning` state, 배너 렌더 | 위 두 함수 | `components/evidence/evidence-file-manager.tsx` |

순수 감지 로직(`detectDeliveryFee`)과 I/O(`extractPdfText`)를 분리해, 감지 규칙을
파일 없이 단위 테스트할 수 있게 한다.

## 5. 감지 규칙 (오탐 방지)

단순 "배송" 매칭은 오탐을 부른다. 예: 점자공보물 영수증의 `"이용문의(구매/취소/배송)"`.
**비용을 뜻하는 패턴만** 매칭한다.

- 매칭 패턴(예): `(배송|운송|발송|택배|운반|배달|퀵)\s*(비|료|요금)` 및
  `박스/포장/발송비`, `퀵서비스` 등.
- 명시 키워드: 배송비, 운송비, 발송비, 택배비, 운반비, 배달료.
- 제외: "배송 안내", "구매/취소/배송", "배송지" 등 비(非)비용 문구.
- 반환에 매칭된 키워드를 담아 추후 로깅/문구 활용 여지를 둔다(현재 배너 문구는 고정).

## 6. 기술 메모

- **신규 의존성**: `pdfjs-dist`. Next.js 16 + React 19 클라이언트 컴포넌트에서
  동적 import 하고 `GlobalWorkerOptions.workerSrc`를 설정한다(legacy/worker 이슈 주의).
- 추출은 첨부 즉시 클라이언트에서 수행(파일이 이미 base64로 클라이언트에 있음).
  서버 왕복 없음.
- 추출 실패(암호화 PDF, 텍스트 없는 스캔 PDF 등)는 조용히 통과(경고 없음).

## 7. 테스트

- `detectDeliveryFee` 순수 함수 vitest 단위 테스트:
  - 점자 견적서 텍스트("박스/포장/발송비 44,352") → 감지.
  - "운송비", "택배비 3,000원" → 감지.
  - "이용문의(구매/취소/배송)", "배송지 주소" → 미감지(오탐 방지).
  - 빈 문자열/일반 물품 영수증 → 미감지.

## 8. 비범위 (YAGNI)

- 이미지 OCR / AI 비전 분석.
- 배송비 금액 자동 추출 및 자동 분개.
- 기존에 첨부된 증빙(과거 데이터) 일괄 재검사.
