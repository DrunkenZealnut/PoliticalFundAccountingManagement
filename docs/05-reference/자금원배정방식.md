# 자금원(수입계정) 배정 방식 — 단일 권위 문서

> **대상**: 후보자 회계의 "지출에 자금원(수입계정 `acc_sec_cd` 82~85)을 배정"하는 로직을 **읽거나 새 소비처를 추가**하는 사람.
> **목적**: 흩어져 있던 선행 Draft 플랜 3종과 알고리즘 지식을 **하나의 현재-진실(current truth)** 로 모은다. "무엇이 유효한 결정이고, 무엇이 폐기됐는지"를 여기서 확정한다.
> **한 줄 요약**: 배정은 **보고 생성 시점에만 메모리에서 계산**한다(`acc_book`은 실거래 원본 불변). 모든 살아있는 경로는 단일 SSOT `buildLedgerRows`(Pass0→1→2)를 통과한다.
>
> **Status**: Authoritative · **Date**: 2026-06-21 · **관련 PDCA**: `expense-funding-allocation-review`
> **알고리즘 상세**: [정치자금_수입지출부_생성_주의사항.md](./정치자금_수입지출부_생성_주의사항.md) §2(불변식)·§6(Pass0/1/2). 본 문서는 **결정·맵**, 주의사항은 **방법**.

## 2. SSOT 진입점 (의존 방향: 위→아래)

```
raw acc_book 행 (자금원 82~85 포함)
        │
        ▼
  allocateCandidateLedgerRows   ← 후보자 보고용 진입점 (메타 보존, 제네릭)
   = Number 정규화 + Pass0 + 후보자 판정 + buildLedgerRows + acc_book_id 메타 재조인
        │
        ▼
  buildLedgerRows = Pass0 → Pass1 → Pass2   ← 배분 알고리즘 SSOT (ledger-allocation.ts)
        │
        ├─▶ buildCandidateReportSummary   → 자금원 4분류 집계 모델(22-1/총괄)
        └─▶ detectCandidateShortfalls     → reallocateFundSources(input).shortfalls (진단, FR-03)
```

| 함수 | 파일 | 역할 |
|------|------|------|
| `buildLedgerRows` | `lib/accounting/ledger-allocation.ts` | **배분 SSOT.** raw `ReallocRow[]` → `LedgerRow[]`. Pass0→1→2 내부 적용 |
| `allocateCandidateLedgerRows` | `lib/accounting/income-expense-report-summary.ts` | 후보자 보고용 진입점. 숫자화+Pass0+게이트+`buildLedgerRows`+메타 재조인(제네릭 `T`) |
| `buildCandidateReportSummary` | 〃 | `allocateCandidateLedgerRows` → 자금원 4분류(보조금/보조금외/후보자자산/후원회기부금) 집계 |
| `detectCandidateShortfalls` | 〃 | 동일 전처리 후 `reallocateFundSources(input).shortfalls`만 추출. 통장 부족 진단(순수·멱등) |
| `planAllocationPersist`/`applyPlanInMemory` | `lib/accounting/persist-allocation.ts` | export용 (계정×과목) 분할 행 세트 materialize. 내부 `buildLedgerRows` 사용 |

> `buildLedgerRows`가 Pass0(`adjustNegativeIncome`)를 **내부 적용**하므로, 이 함수를 경유하는 모든 소비처는 음수수입 정규화를 자동 상속한다. `allocateCandidateLedgerRows`가 앞단에서 한 번 더 적용하지만 Pass0는 **멱등**이라 무해하다.

## 3. 배분 파이프라인 (요약 — 상세는 주의사항 §6)

- **Pass0 `adjustNegativeIncome`** (`adjust-negative-income.ts`): 음수 수입(`incm_sec_cd=1 && acc_amt<0`) → 양수 지출(`incm_sec_cd=2`, abs). 멱등.
- **Pass1 `reallocateFundSources`** (`fund-realloc.ts`): 단일 현금풀 캐스케이드. 자금원 `S`의 지출이 그 시점 가용액을 초과하면 부족분을 `overflowPriority`(기본 `[84,83,82]`)의 잉여 자금원으로 이동. 한 지출이 여러 자금원으로 쪼개지면 `splitGroupId`로 묶고 `split-keep`/`split-moved` 표기. **과목(`item_sec_cd`) 절대 불변(I4)**. 통장 부족 시 `shortfalls` 산출.
- **Pass2 `allocateIncomeToItems`** (`item-allocation.ts`): 자금원별로 수입을 충당 과목으로 FIFO 재태깅. **지출 과목 불변.**
- **정렬 SSOT**: `compareAccDateTime`(acc_date만; 시분초 미사용) → `incm_sec_cd`(수입 우선) → `acc_book_id`.

**불변식 I1~I4** (주의사항 §2): I1 합 보존 · I2 무음수(통장≥0 가정) · I3 멱등 · I4 지출 과목 불변.

## 4. 전제와 그 위반 (은폐 금지)

- **전제**: 통장 총잔액이 항상 ≥ 0이면 어떤 (계정×과목)도 음수가 되지 않는다(I2).
- **위반**: 총지출 > 총수입(= 데이터 오류)이면 Pass1이 원 자금원에 음수를 잔류시키고 `Shortfall{acc_book_id, acc_date, accSecCd, shortAmt}`를 산출한다.
- **처리(FR-03)**: `detectCandidateShortfalls(rawRows)`로 감지 →
  - **page 총괄**(`income-expense-report`): 빨강(Error) 배너로 자금원·일자·금액·건수 노출.
  - **HWPX route**(`accounting-report`·`income-ledger`): `console.warn`(상세) + 응답 헤더 `X-Allocation-Shortfall`(**건수만** — 거래 상세는 서버 로그에만, 민감정보 과다노출 방지).
  - 생성 자체는 막지 않는다(은폐만 금지 — 사용자가 데이터를 교정할 수 있게).
- 정상 데이터(통장≥0)면 `shortfalls`는 빈 배열 → 경고 미표시(오탐 없음).

## 6. 적용 범위 밖 (명시적 한계)

- **비후보자(후원회/정당/국회의원) 자금원·과목 배정** — `acc_sec_cd`가 수입/지출 플래그라 구조가 다름. 현행 무배분. 별도 대형 PDCA 필요.
- **새 배정 규칙/알고리즘 변경** — Pass1/Pass2 로직은 옳다고 판단, 변경하지 않음.
- **영구화(acc_book 분할 write) 재도입** — 보고 시점 계산 방침 유지. scripts 016/017은 사장(018 DROP 권고).
- **음수수입 포함 시 경로 간 미세차** — 모든 행-생성 경로가 `buildLedgerRows`(Pass0 내장)를 경유해 사실상 일치하나, 엄밀 검증은 별도.
