# Design — 자금원 재배분 소액 자투리 방지 + 지출 자금원 보호 (funding-realloc-scrap-guard)

- 기능: `funding-realloc-scrap-guard`
- 단계: Design
- 작성일: 2026-07-01
- Plan 참조: `docs/01-plan/features/funding-realloc-scrap-guard.plan.md`
- 관련 메모: [[fund-source-redistribution]] · [[income-expense-book-funding-realloc]] · [[settlement-must-use-realloc-ssot]] · [[negative-refund-rows-in-aggregation]]

## 1. 개요 / 확정 사실

Plan에서 확정: 데이터 정상(통장 0, **84 −413,483 ↔ 85 +413,483 상쇄**), 58원은 확성장치 540,000(자금원 84)의 재배분 자투리, 사용자 제약 = 지출 과목 불변·자금원 이동 가능·**확성장치는 84 유지(D-2)**.

## 2. 핵심 발견 (Design 결정을 좌우) — 양립 불가

> **확성장치를 자금원 84에 통째 두는 것(D-2)과 "시간순 자금원 잔액 ≥0" 불변식은 동시에 성립할 수 없다.**

- 5/22 확성장치(#331, 540,000, 84) 처리 시점, 자금원 84 가용은 **58원**(예금이자 57 + 네이버 1)뿐.
- 확성장치 540,000을 84에 통째 두면 그 순간 **84 잔액 = 58 − 540,000 = −539,942** (중간 음수).
- 현재 재배분은 이 음수를 막으려 `fund-realloc.ts:115` `useS = min(need, 84가용 58)`로 84에서 58만 쓰고 나머지 539,942를 83으로 이동 → **84:58 잔류 자투리 + 확성장치가 84를 벗어남**.
- v0.24.0.0 자투리 방지(`120-137`)는 **이동분(moves)의 자투리만** 막고, **원 자금원 잔류(useS)** 는 대상이 아니라 58원이 남는다.

**따라서 D-2(확성장치 84 유지)를 지키려면 중간 시점 음수 잔액을 허용해야 한다. 이것이 이 Design의 유일한 근본 결정(OQ-2).**

## 3. 잔액 정책의 근거 (조사)

- `fund-realloc.ts:7-8` / `ledger-allocation.ts:11-14`: "모든 (계정×과목) **시간순 잔액 ≥0**"은 **공식 Fund_Data가 DDL로 강제하는 게 아니라 앱의 설계 선택**(수입 없이 지출 못 한다는 회계 표시 + 공식 프로그램 데이터 구조 모사).
- 자금원별 잔액은 **저장이 아니라 매번 재계산**(`income-expense-book/page.tsx:258-262` `balance = incCum − expCum`, export-sqlite는 OPINION의 전체 balance만 기록). → **중간 음수를 저장하는 스키마 문제는 없다.** 다만 뷰어가 음수를 그대로 렌더(`:373`)해 사용자가 "재배분 안 됨"으로 오인할 여지.
- **최종 잔액(수입−지출)은 재배분 방식과 무관하게 불변**(`settlement-summary.ts:48` 주석: balance는 재배분 불변 → 재산검증 영향 없음). → **결산·재산명세서는 안전.**

## 4. 설계 옵션

### 옵션 B — 시간순 ≥0 유지 + useS 자투리 방지 (D-2 위반)
- `useS`가 소액 자투리면 원 자금원을 스킵(useS=0)하고 부족분 전체를 단독 커버 자금원으로 통째 이동.
- 결과: 58원 자투리는 사라지나, **확성장치가 83으로 통째(540,000) 이동 → 84를 벗어남 → D-2 위반.**
- 시간순 ≥0·기존 불변식·parity 유지(안전). **단 사용자 요구를 못 지킴.**

### 옵션 C — 중간 음수 허용 + 총액 기준 배정 (D-2 충족, 유력)
- 지출은 원 자금원·과목 유지(확성장치 84 통째). 시간순 중간 잔액 음수 허용.
- 자금원 **최종** 잔액을 ≥0으로 맞추기 위해, **총액 부족 자금원(84 −413,483)의 부족분만큼을 총액 잉여 자금원(85 +413,483)으로 통째 지출 이동**(확성장치는 제외, §5 OQ-3).
- 결과: 확성장치 84 유지, 58원 자투리 0, 최종 잔액 정합.
- **대가**: ① 뷰어에 중간 음수 잔액 표시(사용자 오인 방지 UI 필요) ② 불변식 "시간순 ≥0"→"최종 ≥0"로 완화 ③ 광범위 회귀(§6).

**추천**: D-2가 사용자 최우선이므로 **옵션 C**. 단 대가가 크므로 OQ-2에서 사용자 명시 승인 필수.

## 5. 이동 대상 선택 (OQ-3, 옵션 C 채택 시)
- 84 부족분 **413,483**을 85로 옮길 84 지출을 고른다. **확성장치(540,000) 제외.**
- 규칙 후보: (a) 부분합으로 413,483에 근접하는 통째 지출 조합, (b) 정확히 안 맞으면 최소 1건만 분할(자투리 1개 허용), (c) 결정적 순서(금액 내림차순 등).
- 예: 로고송 800,000·수당류 등에서 413,483 근사 조합. Design 상세는 구현 시 픽스처로 검증.

## 8. 결정 (확정) / 미해결

### 확정 (Plan에서, 사용자)
- D-1 지출 과목 불변·자금원 이동 가능 / D-2 확성장치 84 유지 / D-3 확성장치 보호 규칙 + 데이터 정상.

### D-4 (OQ-2 확정) = 옵션 C (사용자: "부족분은 나중에 자산으로")
- 확성장치는 84 유지, 5/18 시점 부족분은 **미래 같은 자금원(후보자자산) 수입으로 시간순 충당**. 재현 확인: 5/18 확성장치 부족분(539,943)은 5/26(+1,000,000)·6/10(+8,300,000) 자산 입금이 해소. 중간 시점 84 음수는 **미래 자산으로 메워지는 일시적 표시**.
- **근거**: 확성장치 84 유지는 다른 자금원 여유(85 잉여 413,483 < 필요 539,943, 126,460 부족)로는 불가능 → 미래 자산 충당(중간 음수)만이 유일한 84 유지법. 최종 잔액·합·통장총잔액·결산은 **불변**(안전).
- 구분: "확성장치를 83으로 옮기는 것"은 거부(D-2), "84에 두고 미래 자산으로 메우는 일시적 마이너스"는 수용.

### 미해결 (구현 상세)
- **OQ-3**: 84 **최종** 부족분(413,483)을 85 잉여로 옮길 지출 선택 규칙(확성장치 제외, 부분합·결정성).
- **OQ-4**: 뷰어 중간 음수 잔액 표시 — 그대로 두되 "미래 수입으로 충당 예정" 설명/배지로 오인 방지.
- **OQ-5**: 불변식 "시간순 ≥0" → "최종 ≥0 + 중간 음수 허용" 완화 시 T15/L7/settlement 테스트 갱신 범위.

## 9. 리스크
- **재배분 SSOT + 불변식 변경 → 6개 산출물 + 다수 테스트 광범위 회귀.**
- **공식 형식 정합**: 중간 음수 잔액이 선관위 제출물(수입·지출부)에 어떻게 비칠지 — 사용자/실무 검증 필요.
- **오인 리스크**: 뷰어 음수 잔액을 "오류"로 볼 수 있어 UI 설명 필수.
- 최종 잔액·합·통장총잔액은 불변이라 결산·재산검증은 안전(조사 확인).
